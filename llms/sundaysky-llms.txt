# SundaySky

> Enterprise video personalization platform. SundaySky renders individually personalized videos in real time from customer data, and delivers them through its own HTML5 player. It publishes one documented HTTP API — the SundaySky Video API — plus a client-side player web component with a rich browser event surface. There is no self-serve developer portal, no OpenAPI, and no public pricing; access is sold and provisioned to enterprise customers.

## API

- [SundaySky Video API](https://help.sundaysky.com/hc/en-us/articles/6000894076957-Using-the-SundaySky-API-to-Connect-Data): POST `https://apis.sundaysky.com/get-video/player-session/{sundayskyVideoId}`. Send a flat JSON object of viewer personalization fields with `Content-Type: application/json`; optionally send the viewer's `User-Agent` so device and browser are detected correctly. Returns a base64 string — the player session — which is pasted into the player embed snippet, or decoded to extract the video stream URL and captions file URL for a third-party player. CTAs and analytics only work in the SundaySky player. The integration is storage-less: personalization data is purged after the video is generated.
- Authentication: none. There is no API key, token, or Authorization header. The SundaySky Video ID in the path is the only credential — a capability URL. Get it from the video's embed code snippet.
- Field names are NOT global. Each video's accepted JSON keys are configured by the customer in the Studio's Map Fields window and are case-sensitive. Add a lowercase `id` field carrying a unique per-viewer value if you want that viewer's behavior attributed in SundaySky reports.
- Response codes: 200 OK (base64 returned), 30X temporary redirect (follow `location`), 40X malformed or unsupported request, 501 not implemented. An unknown video ID returns 500 with a parameter-validation message, not 404.
- No published rate limits, no version segment, no idempotency contract, no pagination — the public surface is this single operation.

## Player

- [Embedding the SundaySky Player in a Webpage](https://help.sundaysky.com/hc/en-us/articles/4897270366365-Embedding-the-SundaySky-Player-in-a-Webpage): two embed methods. Use **JavaScript** if you need the API data connector, NPS/custom surveys, advanced player configuration, or any event tracking. Use **iframe** for a short, CSS-isolated, auto-updating embed that supports none of those.
- [Integrating with Player Events](https://help.sundaysky.com/hc/en-us/articles/360009316897-Integrating-with-Player-Events): the `<sundaysky-video>` custom element emits browser CustomEvents — `load`, `playRequested`, `playStart`, `progress` (every 1%), `scene`, `ended`, `error`, `ctaShow`, `ctaHide`, `ctaClicked`, `userAction`, `transcript`, `transcriptClicked`, `survey`, `surveySubmit`, `Time to First Frame`, `Video Played`. Most carry `detail.videoUrl`, `detail.videoFormat` and `detail.sessionId`. `ctaClicked` and `transcriptClicked` are cancelable via `preventDefault()`. These are client-side DOM events, NOT server-delivered webhooks — SundaySky publishes no webhook surface.
- Player library: `https://play.sundaysky.com/main/sundaysky-player.grey.en-us.min.js` — CDN-distributed and unversioned; the path segment `main` floats, so callers cannot pin a build.
- [Content Security Policy for the player](https://help.sundaysky.com/hc/en-us/articles/27302852000541-Content-Security-Policies-Required-for-the-SundaySky-Player): exact directive set required to embed, including `script-src 'self' play.sundaysky.com 'unsafe-inline'` and `connect-src 'self' blob: *.sundaysky.com`.

## What SundaySky does not publish

Recorded so an agent does not waste calls looking: no OpenAPI or Swagger document on any host; no GraphQL endpoint; no MCP server; no A2A agent card; no `/.well-known/` document of any kind; no security.txt or vulnerability disclosure program; no server-delivered webhooks or AsyncAPI; no server-side SDK in any package registry; no CLI; no sandbox or test credentials; no published rate limits; no public pricing page. Note that `app.sundaysky.com` and `studio.sundaysky.com` answer HTTP 200 with an identical HTML single-page-app shell for *every* path including `/openapi.json` and `/.well-known/agent-card.json` — those are catch-all routes, not documents.
